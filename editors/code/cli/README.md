# fpp-diagram-render

Command-line rendering of FPP diagrams to SVG, using the same pipeline as the
VS Code extension's diagram panel:

1. `fpp-diagram --format sprotty` (the Rust `fpp_diagram` lowering the language
   server uses) produces a sprotty `SGraph`.
2. Labels are sized from font metrics (the webview measures them in the DOM).
3. The extension's ELK layout (`src/diagram/layout.ts`,
   `src/diagram/layout-config.ts`) places nodes, ports and labels.
4. The laid-out graph is written as standalone SVG with the webview's shapes
   and stylesheet (`webview/css/diagram.css`, theme variables resolved).

## Build

```sh
cargo build --release -p fpp_diagram --bin fpp-diagram   # repo root
cd editors/code && yarn install && yarn build            # emits dist/fpp-diagram-render.js
```

## Use

```sh
# One component from the F Prime framework sources
node dist/fpp-diagram-render.js --name Svc.CommandDispatcher -o CommandDispatcher.svg \
    $FPRIME/cmake/platform/unix/Platform/PlatformTypes.fpp \
    $(find $FPRIME/Fpp $FPRIME/Fw $FPRIME/Svc $FPRIME/Drv $FPRIME/Os $FPRIME/Utils $FPRIME/default/config -name '*.fpp')

# A topology, pruning unconnected ports
node dist/fpp-diagram-render.js --kind topology --name Ref.Ref --hide-unused-ports -o Ref.svg <files...>

# A component block diagram: one port per declaration, labelled "name: [size] Type"
node dist/fpp-diagram-render.js --name Svc.CommandDispatcher --compact-ports --theme light -o CommandDispatcher.svg <files...>

# A topology with each imported topology drawn as one node
node dist/fpp-diagram-render.js --kind topology --name Ref.Ref --view collapsed --bundle-edges \
    --hide-unused-ports --hide-pattern-connections --theme light -o Ref.svg <files...>

# Everything a design document needs for a topology (see "Design documents")
node dist/fpp-diagram-render.js --kind topology --name Ref.Ref --document img/ \
    --hide-pattern-connections --theme light <files...>

# PNG, if wanted (any SVG rasterizer works; headless Chrome shown)
google-chrome --headless=new --screenshot=CommandDispatcher.png --window-size=400,1100 CommandDispatcher.svg
```

Multiple `.fpp` files may be given; `include "..."` directives are resolved
relative to each file and inlined before analysis, so a whole source tree can be
passed. The `fpp-diagram` binary is found in `target/{release,debug}` of the
workspace or on `PATH`; override with `--fpp-diagram`.

`--kind` accepts `component` (default), `topology`, and `connectionGroup`
(`--name <topology>.<group>`). State machines are not rendered by this tool;
`fpp-diagram --format mermaid` already emits them as Mermaid text.

Only the FPP model is read. A topology or component that has been designed in
FPP but has no implementation renders the same as one that has.

## Options for readable diagrams

| Option | Effect |
| --- | --- |
| `--view collapsed` | Each directly imported topology is one dashed node carrying its declared ports. The diagrammed topology's own declared ports are chevrons on the left (inputs) and right (outputs). A connection that names an instance inside an imported topology is drawn dashed, ending on the node's boundary. |
| `--bundle-edges` | Parallel connections between the same two elements become one thick line with a slash and a `/N` count. |
| `--hide-unused-ports` | Unconnected ports of component instances are not drawn. |
| `--hide-pattern-connections` | Connections generated by connection patterns (`command`, `event`, `telemetry`, `text event`, `time`, `health`, `param`) are not drawn. They are matched by connection graph name, so a hand-written graph named like a pattern graph (`Command`, `Events`, ...) is left out too. |
| `--compact-ports` | Component diagrams: a port array is one port labelled `name: [size] Type` instead of one port per element. |
| `--hide-special-ports` | Component diagrams: the framework special ports (command, event, telemetry, time, parameter) are not drawn. |
| `--theme light` | Pale fills and dark text on white, for documents. |

## Design documents

`--document <dir>` (with `--kind topology`) writes, for `--name` and every
topology it imports, directly or indirectly:

- `<topology>.svg`: the collapsed, bundled diagram with unused ports hidden.
- `<name>.md`: a Markdown fragment with the top-level image followed by one
  collapsible `<details>` block per imported topology, nested as imported, and
  a legend. Paste or include it in the document; image paths are relative to
  `<dir>`.
- `<name>.html`: one self-contained page holding every diagram. Clicking an
  imported topology opens its diagram; a trail at the top leads back.

Markdown renderers do not run scripts and show an SVG as a static image, so
the Markdown fragment expands by `<details>` and the click-through lives in the
HTML page.
